## Research gap (synthesis)
1. LLM test generation is mature for **software unit tests** (L05–L08) but rarely produces **executable system tests from natural-language requirements** (L02, L03).
2. Embedded LLM work mostly uses **simulators or emulators** (L15, L18); real-hardware loops are few and recent (L14, L19).
3. Prior HIL+LLM work relies on **cloud models** (L14, L17 mostly, L19); sovereignty is not addressed (L26).
4. Code-derived oracles **validate bugs** (L09); requirement-derived oracles with traceability are needed.
5. Few systems **diagnose why a hardware test failed** (firmware bug vs faulty test vs wiring vs timing) — diagnosis work is software/cloud only (L20, L21).
